# Megastructure Cleaner Game

## Toolchain and verification

- Open the project root with **Unity 6000.3.8f1** (recorded in `ProjectSettings/ProjectVersion.txt`); it uses URP and the Unity Input System.
- There are no repository build, lint, or test commands, test assemblies, or CI workflows. Use Unity Editor compilation and Play Mode as the focused verification path for changed scenes/features.
- Keep Unity-generated `.meta` files with every new or moved asset. Do not commit `Library/`, `Temp/`, build output, or IDE-generated project files; they are ignored.

## Scenes and runtime flow

- `ProjectSettings/EditorBuildSettings.asset` currently enables `Assets/Scenes/SampleScene.unity` at build index 0 and `Assets/Scenes/MainGameMenu.unity` at index 1. `TrashSystemDemo.unity` is disabled and is for the trash-system demo.
- The menu scene's `MainMenuController` loads `SampleScene`; `SampleScene`'s pause menu returns to `MainGameMenu`. Open the appropriate scene explicitly when testing either flow—building/running currently starts `SampleScene`, not the main menu.
- Scene names used by `SceneManager.LoadScene` must remain present in Build Settings. The current serialized names are `SampleScene` and `MainGameMenu`.

## Code and asset contracts

- Gameplay code is under `Assets/Scripts/` (`Player/`, `Trash/`, `UI/`, and `Settings/`); the menu button-sound and music components live under `Assets/Music/`.
- Treat `Assets/PlayerInputActions.inputactions` as the input source of truth. `Assets/Scripts/Player/PlayerInputActions.cs` is generated by `InputActionCodeGenerator`; never edit it manually—regenerate it through Unity after changing the asset. Runtime code expects the `Player` and `UI` maps and their named actions (including `Interact` and `PauseMenu`).
- Settings UI is created at runtime from `Resources.Load<VisualTreeAsset>("UI/Settings")`; keep `Assets/Resources/UI/Settings.uxml` at that exact path if changing it. Its styles are in `Assets/UI/USS/Settings.uss`.
- Menu, pause menu, crosshair, and settings use UI Toolkit (`.uxml`/`.uss`) and query elements by fixed names. Update the corresponding controller queries when renaming UI elements.
- `SettingsPanelController` intentionally creates a separate runtime `PanelSettings`; nested `UIDocument`s cannot share the parent panel in this project.

## Feature-specific setup

- Follow `Assets/Docs/GrabSystem.md` for grab/interact scene setup: `PlayerRaycastInteract` raycasts only its configured `Interact Layer`, and `Grabable` requires a `Rigidbody`.
- Follow `Assets/Docs/trash-location-setup.md` for trash setup. Runtime-spawned trash must be registered with `TrashLocation.RegisterRuntimeTrash`; remove tracked trash through `TrashItem.Remove()` rather than destroying it directly.
