# Система чекпоинтов и зон смерти

Методичка по настройке и расстановке чекпоинтов, зон смерти и респавна.

---

## Обзор системы

| Компонент | Файл | Роль |
|---|---|---|
| `CheckPoint` | `Scripts/Checkpoint/CheckPoint.cs` | Триггерная зона. Срабатывает **один раз** при входе игрока, становится точкой возрождения и сохраняется на диск |
| `CheckpointManager` | `Scripts/Checkpoint/CheckpointManager.cs` | Мозг системы. Один на сцену: загружает сейв, запоминает активный чекпоинт, выполняет респавн |
| `DeathZone` | `Scripts/Checkpoint/DeathZone.cs` | Триггерная зона смерти. При входе игрока — респавн на последнем чекпоинте |
| `ScreenFader` | `Scripts/UI/ScreenFader.cs` | Затемнение экрана при респавне (Canvas создаёт сам) |
| `GameProgress` | `Scripts/Intro/GameProgress.cs` | Хранение сейва (PlayerPrefs), переживает перезапуск игры |
| Меню редактора | `Editor/CheckpointMenu.cs` | Быстрое создание объектов: ПКМ в иерархии → **Чекпоинты** |

### Как это работает (флоу)

```
АКТИВАЦИЯ ЧЕКПОИНТА
Игрок входит в триггер CheckPoint
  → чекпоинт становится активным (один раз за сессию)
  → его ID записывается в PlayerPrefs (сразу, надёжно)
  → запись в консоль: "[Checkpoints] Активный чекпоинт: ... Прогресс сохранён."

ЗАПУСК ИГРЫ
"Продолжить" в меню
  → CheckpointManager читает ID из PlayerPrefs
  → находит чекпоинт с этим ID на сцене
  → мгновенно ставит игрока в его SpawnPoint (без затемнения)
  → сейва нет → игрок стоит там, где размещён в сцене (или в Default Spawn)

СМЕРТЬ (DeathZone / падение за карту)
Вход в зону смерти
  → управление игрока замораживается, скорости обнуляются
  → экран затемняется (~0.3 сек)
  → телепорт на SpawnPoint последнего чекпоинта
  → управление возвращается
  → экран проявляется (~0.3 сек)

"НОВАЯ ИГРА" в меню
  → сейв чекпоинта сбрасывается, игрок начинает со старта
```

## Часть 1. Первичная настройка сцены (один раз)

### Шаг 1. Создать системный объект

1. **ПКМ в иерархии → Create Empty**, назвать `CheckpointSystem`.
2. Выделить, **Add Component** → добавить два компонента:
   - `CheckpointManager`
   - `ScreenFader`

> ⚠️ **Важно:** `ScreenFader` нельзя вешать на объект, где есть `UIDocument` (меню, HUD) —
> он создаёт собственный Canvas и конфликтует. Только пустой объект.

3. Ссылки в `CheckpointManager` (`Player`, `Default Spawn`, `Screen Fader`) можно оставить
   **пустыми** — всё найдётся автоматически. Заполнять вручную нужно только в особых случаях
   (например, если на сцене несколько объектов с `PlayerMovements`).

### Шаг 2. Параметры CheckpointManager (инспектор)

| Параметр | По умолчанию | Что делает |
|---|---|---|
| `Player` | пусто (автопоиск) | Ссылка на игрока с `PlayerMovements` |
| `Default Spawn` | пусто | Стартовая точка, если сейва чекпоинта нет. Пусто = игрок остаётся на своём месте в сцене |
| `Default Spawn Height Offset` | 0.1 | Подъём над стартовой точкой |
| `Respawn Lift` | 0.05 | Подъём над точкой чекпоинта при телепорте (защита от застревания в полу) |
| `Enable Fall Death` | ✓ | Страховка: гибель при падении ниже порога |
| `Fall Death Y` | −50 | Мировой Y, ниже которого игрок считается погибшим. Ставь ниже самого низкого участка уровня |
| `Screen Fader` | пусто (автопоиск) | Затемнитель экрана |
| `Debug Log` | ✓ | Логи в консоль |

### Шаг 3. Параметры ScreenFader (инспектор)

| Параметр | По умолчанию | Что делает |
|---|---|---|
| `Fade Out Duration` | 0.3 сек | Скорость затемнения (смерть) |
| `Fade In Duration` | 0.3 сек | Скорость проявления |
| `Fade Color` | чёрный | Цвет затемнения |
| `Sorting Order` | 1000 | Порядок отрисовки. Должен быть выше всего UI, иначе затемнение будет «под» меню |

## Часть 2. Расстановка чекпоинтов

### Создание

**ПКМ по пустому месту в иерархии → Чекпоинты → CheckPoint**

(или меню сверху: GameObject → Чекпоинты → CheckPoint)

Создаётся объект, уже содержащий:
- `BoxCollider` (IsTrigger ✓, размер 4×3×4)
- Компонент `CheckPoint` с автоматическим ID
- Ровно один дочерний `SpawnPoint`

### Структура объекта

```
CheckPoint_Мост            ← BoxCollider (IsTrigger) + CheckPoint
└── SpawnPoint             ← точка, где появится игрок при респавне
```

### Два важных места: зона триггера и точка спавна

1. **Габариты CheckPoint** (Box Collider → Size) — это зона срабатывания.
   Растяни так, чтобы игрок **не мог пройти мимо**: на всю ширину прохода/коридора/моста.
   Высоты 3 обычно достаточно.

2. **SpawnPoint** — куда игрок попадёт при смерти. Правила размещения:
   - **На полу** (не в воздухе — иначе игрок при респавне упадёт)
   - **Не внутри стен и коллайдеров** (иначе застрянет)
   - В **безопасном месте**: подальше от края, с которого игрок упал в зону смерти!
     Классическая ошибка: чекпоинт у пропасти → SpawnPoint на самом краю → игрок
     возрождается, делает шаг и снова умирает в бесконечном цикле.
   - Желательно на расстоянии 1–2 м от зоны срабатывания и от опасности.

3. **Поворот SpawnPoint** = поворот игрока при возрождении. Направь синюю стрелку
   (ось Z) в сторону, куда игрок должен смотреть.

### Параметры CheckPoint (инспектор)

| Параметр | Что делает |
|---|---|
| `Checkpoint Id` | Уникальный ID (0, 1, 2...). Заполняется автоматически. **Не меняй после того, как прогресс уже сохранён!** |
| `Spawn Point` | Ссылка на дочернюю точку возрождения |
| `Spawn Height Offset` | Дополнительный подъём игрока над точкой (0.1 по умолчанию) |
| `Log Activation` | Лог активации в консоль |

### Правила ID (критично!)

- ID уникальны в пределах **всей игры**, а не одной сцены.
- ID хранится в сейве игрока. **Поменял ID существующего чекпоинта — у игроков
  сломается сохранение.** Добавляй новые чекпоинты только с новыми ID в конце.
- Удаление чекпоинта: если у игрока сохранён его ID, при загрузке появится
  предупреждение в консоли, и игрок начнёт со старта. Если чекпоинт надо убрать —
  сначала убедись, что это не последний пройденный у игроков.
- При запуске игры менеджер проверяет дубликаты ID и пишет красную ошибку в консоль.

### Сколько чекпоинтов ставить

- После каждого «сложного» участка: после платформинга, ловушек, узких проходов.
- В начале новой зоны/секции уровня.
- Практика: игрок не должен терять больше 1–2 минут прогресса при смерти.
- Слишком много — тоже плохо (обесценивает чекпоинты), разумно 1 на «комнату».

## Часть 3. Зоны смерти

### Создание

**ПКМ в иерархии → Чекпоинты → DeathZone**

Создаётся объект с `BoxCollider` (IsTrigger ✓, 10×2×10) и компонентом `DeathZone`.

### Расстановка

- Растяни `Box Collider → Size` (или Scale объекта) так, чтобы зона **полностью
  накрывала опасность**: всю пропасть, всю лаву, всю зону яда.
- Ставь зону **ниже уровня пола** — чтобы игрок гарантированно «провалился»
  в неё, а не задел краем при прыжке. Например, для пропасти: зона на глубине
  −2…−5 м под краем.
- Один DeathZone можно растянуть под весь уровень (например, огромный куб
  под всей картой как «пойматель падений») — но надёжнее совмещать с
  `Fall Death Y` в менеджере.
- Зон можно сколько угодно, настраивать в них нечего (только лог в консоль).

### Страховка от падения за карту

Помимо DeathZone, `CheckpointManager` проверяет в `Update`: если игрок опустился
ниже `Fall Death Y` (−50) — считается погибшим. Это ловит дыры в геометрии,
где ты забыл поставить зону. Держи включённой.

## Часть 4. Сохранение и «Продолжить»

- Сейв пишется в `PlayerPrefs` (реестр на Windows) в момент активации чекпоинта —
  не по таймеру, не при выходе. Даже если игрок вырубит ПКД сразу после активации,
  прогресс сохранён.
- Меню:
  - **«Продолжить»** — игрок появляется на сохранённом чекпоинте, интро не показывается.
  - **«Новая игра»** — сейв чекпоинта сбрасывается, игрок начинает со старта
    (интро проигрывается).
- Отладка сброса: `GameProgress.ResetProgress()` сбрасывает всё (в т.ч. чекпоинт) —
  вызывается по F9, если включено в `IntroCutsceneController`.

## Часть 5. Проверка работоспособности

1. **Активация:** добеги до чекпоинта. В консоли:
   ```
   [CheckPoint] 'CheckPoint' (ID 0): игрок вошёл, чекпоинт активирован.
   [Checkpoints] Активный чекпоинт: 'CheckPoint' (ID 0). Прогресс сохранён.
   ```
2. **Смерть:** прыгни в DeathZone. Экран мигнёт чёрным, игрок окажется
   на SpawnPoint последнего чекпоинта.
3. **Перезаход:** выйди из Play-режима, запусти снова → «Продолжить» →
   игрок сразу на сохранённом чекпоинте.
4. **Новая игра:** меню → «Новая игра» → игрок на старте, чекпоинт сброшен.

## Часть 6. Решение проблем

| Симптом | Причина | Решение |
|---|---|---|
| Чекпоинт не срабатывает | Триггер маленький, игрок обходит его | Увеличь `Box Collider → Size` |
| Чекпоинт не срабатывает | На игроке/зоне `Is Trigger` выключен | Компоненты включают его сами в Awake — проверь, что скрипты на месте |
| Респавн внутри пола / игрок проваливается | SpawnPoint под полом или внутри коллайдера | Подними SpawnPoint над полом, увеличь `Spawn Height Offset` |
| Игрок умирает по кругу | SpawnPoint слишком близко к опасности | Отодвинь SpawnPoint от края/зоны смерти |
| «Сохранённый чекпоинт не найден» | ID сейва не совпадает с ID на сцене | Не меняй ID; пересохрани прогресс, пройдя чекпоинт заново |
| Красная ошибка «ID используется у N чекпоинтов» | Дубликаты ID | Проставь уникальные ID вручную |
| Два SpawnPoint у чекпоинта | Дубль от старой версии меню | ПКМ по компоненту → «Убрать дубликаты SpawnPoint» |
| Нет затемнения | `ScreenFader` отсутствует на сцене | Добавь на `CheckpointSystem` (или другой пустой объект) |
| Затемнение под меню | `Sorting Order` слишком маленький | Увеличь `Sorting Order` в ScreenFader |
| Затемнение не работает в паузе | — | Не случится: используется `unscaledDeltaTime` |

## Часть 7. Планы на будущее (не реализовано)

- Визуальный маркер чекпоинта (светящийся столбик) и звук активации.
- Эффекты на разные типы зон смерти (цвет затемнения, надпись «Вы погибли»).
- Несколько слотов сохранений (потребует перехода с PlayerPrefs на JSON-файл).
- Сейв позиции игрока между чекпоинтами (сейчас сейвится только чекпоинт).
